## شكل الرد — ثابت دائماً

```json
{ "success": true,  "data": { }, "error": null }
{ "success": false, "data": null, "error": "رسالة عربية مفهومة للمستخدم" }
```

رمز HTTP هو **200 في الحالتين** ما عدا رفض المصادقة (403). حقل `success` هو الفيصل،
لأن فشل التحليل خطأ مستخدم لا خطأ سيرفر — والواجهة تعرض `error` كما هو.

## الإجراء `add` — إضافة حركة بالعربي

الطلب:
```json
{ "action": "add", "text": "اليوم صرفت 20 ريال عند المصنع" }
```

الرد:
```json
{
  "success": true,
  "data": {
    "entry": {
      "id": 1,
      "spent_at": "2026-09-19T21:00:00.000Z",
      "amount": 20,
      "currency": "SAR",
      "direction": "expense",
      "category": "أخرى",
      "vendor": "المصنع",
      "note": "صرف عند المصنع",
      "raw_text": "اليوم صرفت 20 ريال عند المصنع",
      "createdAt": "2026-09-20T16:12:01.740Z"
    }
  },
  "error": null
}
```

`spent_at` يُخزَّن كبداية اليوم **بتوقيت الرياض** — أي `T21:00:00.000Z` لليوم السابق.
هذا صحيح ومقصود؛ لا تصلحه بقصّ التاريخ في الواجهة، استخدم `list` الذي يرجّعه `YYYY-MM-DD` جاهزاً.

## الإجراء `list` — قراءة كل الحركات

الطلب:
```json
{ "action": "list" }
```

الرد:
```json
{
  "success": true,
  "data": {
    "currency": "SAR",
    "entries": [
      {
        "id": 4,
        "spent_at": "2026-09-20",
        "amount": 1250,
        "currency": "SAR",
        "direction": "expense",
        "category": "مواد خام",
        "vendor": "مورد جدة",
        "note": "شراء قماش",
        "raw_text": "شريت قماش بـ ١٢٥٠ ريال من مورد جدة",
        "created_at": "2026-09-20T16:12:08.163Z"
      }
    ],
    "totals": {
      "today": 1270,
      "month": 1720,
      "income_month": 3000,
      "net_month": 1280,
      "count": 4,
      "by_category": [{ "category": "مواد خام", "amount": 1250 }]
    }
  },
  "error": null
}
```

- `entries` مرتّبة تنازلياً بالتاريخ ثم بالـ `id`.
- `spent_at` هنا **`YYYY-MM-DD`** بتوقيت الرياض — جاهز للعرض بلا معالجة.
- كل مبالغ `totals` للمصروفات فقط عدا `income_month` و `net_month`.
- `by_category` للشهر الجاري ومرتّبة تنازلياً.

## الأخطاء المتوقعة

| الحالة | الرد |
|---|---|
| مبلغ غير مفهوم | `"ما قدرت أفهم المبلغ من الجملة. جرّب صيغة مثل: صرفت 20 ريال عند المصنع"` |
| نص بلا أي بيانات مالية | `"Model output doesn't fit required format"` ← **يحتاج رسالة أوضح** |
| `action` غير معروف | `"إجراء غير معروف. استخدم add أو list"` |
| فشل التخزين أو القراءة | رسالة الخطأ من عقدة Data Table |

## ملاحظات تشغيلية مكتسبة

- **مخرجات Information Extractor متداخلة تحت `output`** وليست في جذر `$json`.
  عقدة `بناء السجل` تتعامل مع الشكلين احتياطاً.
- **عقدة `قراءة الحركات` تحتاج `alwaysOutputData: true`**. بدونها، جدول فاضٍ ينتج صفر عناصر،
  فلا تعمل العقد التالية ولا يُرسل أي رد — والطلب يعلّق حتى ينتهي وقته.
- **إرسال العربي من curl على ويندوز يصل مشوّهاً** ما لم يُرسَل من ملف UTF-8
  عبر `--data-binary @file`. اختبار `-d 'نص عربي'` يعطي نتائج خاطئة مضلّلة.
- زمن الاستجابة: `add` ≈ 1.6–2.3 ثانية · `list` ≈ 0.6 ثانية.
  كلاهما داخل حد Vercel (10 ثوانٍ) فلا حاجة لنمط المهام غير المتزامنة.
- النموذج: `claude-haiku-4-5-20251001` بحرارة 0 عبر credential Anthropic المباشر
  (تفادياً لفخ `maxTokens` في OpenRouter الذي يُرجع مخرجات فارغة).
